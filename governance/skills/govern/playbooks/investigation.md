### Investigation

**Read-only. The deliverable is a cited answer, not a change.**

1. Restate the question and what a complete answer must cover.
2. Read the code, history, tests and feature map. Where the answer is a fact you can observe, run the app and observe it instead of reasoning about it.
3. Separate what you observed from what you infer. Cite a file and line, a command and its output, or a commit for every claim.
4. Do not edit tracked files. If the investigation shows a change is needed, say so and stop; the change is a new task under the Feature, Bug fix or Refactor playbook.

**Reply:** the answer first, then the evidence, then what remains unknown.
